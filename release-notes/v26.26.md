# v26.26

The one where a year of hard-won Power BI knowledge stops living on one laptop.

**The migration**

Four files under `~/.claude/rules/` had been collecting environment notes for about a year: the TMDL
indentation rule that silently deletes format strings, the PBIR tag whose absence errors a published
report per visual, the gateway-free Fabric refresh recipe, roughly a hundred things learned by
breaking something first. None of it travelled. Not to a Codespace, not to a second machine, not to
anyone else running these plugins.

All 110 of those facts now live in the skill that owns the topic. Three new reference files carry
the rest:

- **`pbip:tmdl` `references/authoring-gotchas.md`** is the failure-mode companion to a skill that
  documented syntax only. It opens on *do not accept "it parsed" as the check*, because the worst
  TMDL mistakes deserialize clean and corrupt the model anyway.
- **`pbi-desktop:connect-pbid` `references/desktop-lifecycle.md`** covers the Desktop process rather
  than the Analysis Services connection, and names the headless substitutes up front.
- **`pbi-desktop:connect-pbid` `references/assembly-discovery.md`** teaches the probe that finds an
  ADOMD assembly and how to match its target framework to the host, instead of hardcoding one
  machine's path.

**Codespaces**

`.devcontainer/` plus `scripts/bootstrap-agent-env.sh` register the marketplace, install the Linux
toolchain, and print a capability report before the first turn. That report exists because the
expensive failure is an agent spending turns installing `pbir` on Linux, where it has no wheel and
no sdist. Where a route is Windows-only or Desktop-only, the skill now names the substitute in the
same sentence: render server-side with `ExportTo` instead of screenshotting Desktop, validate TMDL
with the bundled `tmdl-validate` binary, author PBIR by hand from the `pbip:pbir-format` templates.

**Corrections, all of which were making agents fail**

- `dataType` is `Integer`, never `Int64`. `pbir validate` rejects `Int64` and publish fails.
- `nativeQueryRef` is the field's real native name, not the display label. Six places said
  otherwise, which is the exact cause of a Deneb visual rendering an intact skeleton with all-blank
  cells and no error in Desktop, in `pbir validate`, or in Deneb's own log.
- `fab api` has no `-o` flag and corrupts binary bodies.
- `active: true` on a Values projection makes Desktop render one column and silently drop the rest.
- A standalone `//` line is not TMDL at any indent, and `//` may not trail a declaration, though
  `//` inside a DAX or M expression body is fine. Found and verified during this work, not migrated.
  Four reference files were modelling the invalid shape inside ```tmdl fences.

**Keeping it from happening again**

[`LEARNINGS.md`](../LEARNINGS.md) carries the rule for where a new fact goes: machine-local,
platform- or version-scoped, or universal. `scripts/record-learning.sh` writes a note into the
owning skill and opens a PR, and refuses to put a machine-local fact in a public repo.
`scripts/check-skill-hygiene.py` runs in CI and fails on a version claim with no `Retest:` command,
on a leaked machine path, on a denylisted term, and on a dead markdown link or heading anchor. It
found five broken links on its first run.

**Also**

- `PERSONALIZING.md` described a loading model this fork does not use. A `directory`-source
  marketplace attaches live from the folder: no per-commit cache, no version bump, no
  `plugin update`. The cache that does exist is keyed by version, not commit SHA.
- Plugin manifests and skill versions are back in lockstep, and the five skills that carried no
  `version:` line now have one.
