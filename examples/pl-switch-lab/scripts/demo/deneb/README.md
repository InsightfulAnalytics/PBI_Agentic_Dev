# Deneb P&L spec (page 9: "Odd Rows P&L - Deneb")

Renders the full 13-row x 14-column Odd Rows P&L from a **30-row** dataset.

| File | What |
|---|---|
| `pl_spec.json` | The Vega-Lite v6 spec. 32 transforms, 11 layers. No `width`/`height`: Deneb sizes from the container. |
| `pl_config.json` | Deneb config. `autosize: fit`, transparent view/background. |
| `verify_spec.mjs` | **The gate.** Runs the spec's transforms over the real data and diffs all 182 cells against `../_golden_182.csv`. |
| `sample_rows.json` | The 30 real rows, in the field names Deneb hands the spec. |
| `pl_preview.png` | Offline render, for eyeballing layout without Power BI. |
| `render_local.mjs` | Local PNG renderer that stubs Deneb's `pbiColor` etc. The shared plugin renderer throws `Unrecognized function: pbiColor` on any spec using them. |

## The classic statement (page 10: "P&L - Deneb")

| File | What |
|---|---|
| `pl_classic_spec.json` | Vega-Lite spec for the classic 27-line x 14-column statement. Generated by `gen_classic_spec.py`: edit the generator, not the JSON. |
| `gen_classic_spec.py` | The generator: 22 transforms, 11 layers, palette and sizes as constants. |
| `verify_classic.mjs` | Numeric gate: runs the spec and diffs all 378 cells against an independent JS implementation. |
| `classic_synth_rows.json` | Synthetic 27-row dataset (includes a zero-Budget row for the blank-on-Infinity path). |
| `classic_real_rows.json` | The real 27-row extract (regenerate via `classic_dataset_query.dax`). |
| `classic_dataset_query.dax` | The dataset query the page-10 visual sends: 27 grouped lines x 6 base measures. 14 ms warm vs the SWITCH build's 2,300 ms. |
| `_preview_config.json` | White-background config for previews only: the shipped transparent background makes offline PNGs look like the blank-cell bug. |

Dataset contract: `Line`, `LineKey`, `LineClass` + measures renamed via **displayName** to
`Actual`, `Budget`, `LY`, `YTD Actual`, `YTD Budget`, `YTD LY`. The 8 variance columns and
all formatting are in the spec.

## Re-verify after any spec edit

```bash
# numbers (this is the one that matters)
node verify_spec.mjs pl_spec.json ../_deneb_base.csv ../_golden_182.csv

# layout (use the white preview config -- the shipped transparent bg reads as black offline)
node render_local.mjs pl_spec.json _preview_config.json sample_rows.json pl_preview.png
node verify_classic.mjs pl_classic_spec.json classic_real_rows.json
node render_local.mjs pl_classic_spec.json _preview_config.json classic_real_rows.json classic_preview.png 1860 780
```

Then re-embed with `python ../build_odd_rows_pages.py` (Desktop must be closed).

## The transform chain

    pivot Line          ->   6 rows, one per base item: 5 amount fields + 2 counts
    calculate x7        ->   the 7 derived statement rows (ratios, per-unit)
    fold 13             ->  78 rows (base item x metric)
    pivot "P&L View"    ->  13 rows, one per metric, 6 base-item columns
    calculate x8        ->   the 8 derived column variants (vs LY, Var to Budget, ... )
    fold 14             -> 182 rows
    calculate x7        ->   ordering indices, format flags, the formatted label

**The order is load-bearing.** All 13 row formulas must be evaluated for each of the 6 base
items *before* the 8 variance columns are derived. Derive the amounts first and
"Gross Margin % / vs LY" silently becomes a ratio of differences instead of a difference of
ratios: plausible numbers, no error. That is what `verify_spec.mjs` exists to catch.

## Gotchas hit while building this

- **`fontWeight` is not a Vega-Lite encoding channel.** Dropped silently with a compile
  warning. Subtotal bolding is two mark-level layers filtered on `datum.isSubtotal`.
- After the final `fold`, rows still carry the pre-fold pivot columns (`Actual`, `LY`, ...),
  so "the first numeric field" is not the folded value. Cost an hour of chasing a phantom
  152-cell mismatch that was in the harness, not the spec.
- Field names contain spaces and an ampersand : `datum['P&L View']` everywhere.
- `"YTD Var to Budget %"` overruns a ~130px band. The header text is abbreviated by a
  `replace(datum.col, 'Budget', 'Bgt')` calculate; `datum.col` keeps the full name for the
  tooltip and for verification.
- Expenses are stored **negative**: Gross Profit = Total Income + Total Cost of Sales.

## Provenance

Two specs were authored independently and both verified 182/182 against the golden file.
They converged on an identical transform chain through the second `fold`: good evidence the
chain is the natural one, and differed only in layout. The shipped spec is the second:
it reserves a left gutter and a header band with **spacer entries in the band-scale domain**
(`__label__`, `__header__`) that no datum occupies, which is what buys a real "STATEMENT LINE"
column and the CURRENT PERIOD / YEAR TO DATE group headers.

Two defects were found in it by rendering, after it had been reported as verified:

- the money scaling used `format(v/1e6, '.1f')`: **no group separator**, so `$9790.8M`
  instead of `$9,790.8M`. The numeric check passes either way; only the render shows it.
- the gutter text `limit` clipped "Net Profit per Trading Store".

Both fixed here. The lesson is the same one `verify_spec.mjs` encodes: numeric verification and
visual verification catch different classes of bug, and a spec needs both.
